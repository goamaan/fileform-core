# Full-resolution page images

`pdf.rasterize` exports the complete explicit `PageReference` sequence as PNG or JPEG files in one new directory. Source IDs, zero-based page indices, extra clockwise quarter turns, order and duplicates are preserved. `CommittedArtifact.sourcePages` records each output's page provenance; older result records may omit it. This operation renders whole pages; it does **not** extract embedded image objects.

```sh
fileform pdf pages --input report.pdf --output report-pages --dpi 144 --to png
fileform pdf pages --input report.pdf --input diagram.png --pages '2,1,2,3' --output selected-pages --dpi 300 --to jpeg --quality 0.85
```

Repeat `--input` in source order. `--pages` selects one-based indices from the concatenated inputs. Omit it to export all pages. Missing pages, empty selections and unsupported sources fail the job; nothing is silently skipped. `--dry-run` validates every selected page and emits the typed plan. `--collision rename` keeps both folders, otherwise an existing output fails without replacement. File names are `001.png`, `002.png`, etc. (or `.jpg`), following selection order.

Public clients construct `.pdfRasterize(pages:dpi:quality:)`, with PNG/JPEG output and `.directory` cardinality. Portable recipes retain page order, duplicates, rotations, DPI and quality while rebinding local assets explicitly. The capability inventory advertises both output routes only when the native worker is installed. No PDF engine pack is required.

PDF crop boxes and native plus requested rotation determine output geometry. DPI is explicit (36–600), with pixel dimensions rounded upward and matching resolution metadata (PNG permits physical-resolution integer rounding). PDF points scale at DPI/72. SDR still images use one point per oriented pixel, matching PDF composition. Each output has a white background and sRGB pixels. Screen-visible annotation and filled-widget appearances are drawn into the same cropped/rotated point space; annotations with `shouldDisplay == false` are omitted even if marked printable. Form behavior and signature validity are not retained. PNG losslessly encodes those pixels; JPEG adds lossy encoding at quality 0.05–1. Rasterization loses searchable/editable text, vectors, interactive forms/links, document metadata, bookmarks and digital signatures. It cannot satisfy `requireLossless`.

The shared worker accepts only inherited source and scratch-output descriptors, with typed bounded messages, process-group cancellation, a 60-second CPU limit, 512 MiB file limit and coordinator wall timeout. It validates page geometry before allocation and refuses any requested raster above 64 million pixels or 16384 pixels on either edge; it never silently reduces DPI. Jobs allow 128 source files, 512 MiB combined source bytes, and 1000 selected outputs. PDFs are unencrypted and have at most 1000 pages. Heavy work is serialized by the shared engine gate.

Every output is decoded completely and checked for container, dimensions, complete PNG/JPEG end record, byte count and DPI metadata. All outputs are staged in a private same-filesystem directory. `OutputTransaction` rechecks every source (including unused bound sources), source aliases and collisions at publication and uses an exclusive rename for the whole directory. Failures and cancellation remove staged outputs and preserve originals. No partial output folder is published.

Verification: `swift test --filter pdfRaster` covers crop origins, extra/native rotation, ordered duplicates, provenance, explicit DPI, mixed oriented still images, JPEG, visible shape/highlight/free-text/filled-widget appearance pixels, hidden-annotation exclusion, request/recipe validation, oversized page rejection, source aliases including rename candidates, changed unused sources, and cancellation. `Tools/smoke-pdf-raster.py` exercises the shipped CLI and worker. Pass `--work NEW_DIRECTORY` to retain labeled cropped/rotated fixtures and outputs for native-client checks.

Annotation API reference: the platform SDK’s `PDFAnnotation.h` documents `drawWithBox:inContext:` as drawing in page space relative to the chosen box origin, `shouldDisplay` as screen visibility, and appearance-stream rendering. The worker restores the crop origin exactly once after the CoreGraphics page transform, then neutralizes the copied page’s rotation before invoking `PDFAnnotation.draw(with:in:)` for displayed annotations. PDFKit otherwise applies the native page rotation again to some appearance streams. Fixtures verify both native and requested rotation produce identical appearance pixels.
